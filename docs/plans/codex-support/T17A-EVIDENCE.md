T17A is the first of three T17 children. It closes R07's missing provider resources in wheel/sdist; parent T17 and A05 remain open for bundle freshness, CI matrix and compatibility coverage. The user authorized T17 after asking whether T14 should be next. [T14](04-CODEX-HOST.md#t14--cross-host-acceptance) depends on T17, so the split plan schedules T17A → T17B → T17C before T14.

Wheel archive bytes differed across the two builds, so the hashes above identify the recorded local artifacts rather than asserting reproducible wheel bytes.

The local full offline suite passed. [Initial CI on `ae0556a`](https://github.com/jhesham/cross-llm-delivery/actions/runs/35943843702) passed Ubuntu but failed both new artifact tests on Windows Python 3.11: the runner's older setuptools rejected the repository's existing SPDX `project.license = "MIT"` when the tests invoked it without build isolation. [Setuptools documents](https://setuptools.pypa.io/en/stable/userguide/license_migration.html) SPDX string support from v77. The lead raised `[build-system].requires` to `setuptools>=77` and included the same minimum in the `dev` extra used for no-isolation test builds (`e979372`). Focused tests passed locally after that fix. [CI on corrected source `e979372`](https://github.com/jhesham/cross-llm-delivery/actions/runs/35945164528) passed full tests, Claude/Codex generators, Codex plugin packaging and marketplace catalog smoke on both Windows and Ubuntu.
