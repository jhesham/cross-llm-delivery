# T15 executable contract — optional Codex executor boundary

T15 defines an offline, importable contract in `engine/cld_providers/codex/contract.py`. It does **not** register a provider or make a Codex model call. T16 will wire the contract into the shared process runner, acceptance gate, registry and generated bundles. The fixtures in `tests/fixtures/codex/` are synthetic examples modeled on the official JSONL event shape; they are not captured provider evidence.

Expose `check_capabilities(version_output, help_output)` returning the observed CLI version string, or raise `CodexContractError` with an actionable missing-flag/version message. Require `codex exec` support for `--json`, `--ephemeral`, `--sandbox`, `--cd`, `--model`, `--config` and stdin `-`. Do not set a fixed minimum release from one machine: this is a feature-tested compatibility range, observed on Windows `codex-cli 0.155.1` on 2026-09-25. A nonzero/missing probe belongs to T16's runner; never interpret absent help as support. T16 must run this probe before dispatch and test other target platforms. Reject unrecognized CLI output; version is diagnostic, not proof by itself.

Expose `build_invocation(model, cwd, prompt, *, effort=None, sandbox="workspace-write", depth=0)` returning an object with `argv`, `stdin`, `cwd`, and `env` fields. Require an explicit, nonempty single-line model ID; never guess from Codex defaults or OpenCode's catalog. Optional effort is also explicit and single-line, serialized as `--config model_reasoning_effort="<value>"`; accept only documented spelling `low`, `medium`, `high`, `xhigh`, `max`, `ultra`, while T16 must verify the selected model supports it. Use `codex exec --json --ephemeral --sandbox <read-only|workspace-write> --cd <absolute existing Git worktree> --model <id> [--config ...] -` with the complete prompt on stdin. Do not use `resume`, `--last`, `--skip-git-repo-check`, `--dangerously-bypass-approvals-and-sandbox`, `danger-full-access`, a shell, or a positional prompt. `cwd` and `--cd` must identify the same resolved worktree. Reject `depth != 0`; return `CLD_EXECUTOR_DEPTH=1` in the child environment. Add a short executor-role instruction to the prompt prohibiting CLD/other-provider recursion, committing, pushing, and files outside the slice allowlist; T16 must retain it when constructing task prompts. This guard is defense in depth, not a substitute for isolated worktrees and candidate verification.

Expose `parse_exec_output(stdout, stderr, returncode, *, process_error=None)` returning an outcome with `ok`, `error`, `usage`, and `usage_raw`. Accept a complete JSONL stream with exactly one `thread.started`, `turn.started`, and `turn.completed`; allow `item.*` and unknown valid object events as diagnostics, never as completion or file authority. A missing or duplicate required event, malformed/truncated JSON, `turn.failed`, `error`, a process interruption/timeout/cancel, stderr-only auth error, or nonzero exit is failure even if another event claims completion. Detect auth errors using the shared process classification. Preserve raw completion usage when present; normalize nonnegative integer `input_tokens`/`output_tokens` to `input`/`output`, `cached_input_tokens` to `cache_read`, and derive `total=input+output` only if both are known. Reasoning output is a subset of output: preserve it only in raw usage. Do not add cache to total or claim `cache_write`/USD cost without provider evidence. Missing usage stays unknown, not zero. Ignore final prose and JSONL file-change diagnostics for acceptance; T16 must independently capture and verify the Git diff.

T16 runs via `cld.process` with a finite dispatch timeout/cancellation, separate stdout/stderr artifact paths outside the candidate, and worktree containment before diff capture. Retain raw usage and process metadata in the ledger. Exact model selection must enter the existing model-validation and admission policies, with unknown cost reported as unknown and denied under a cost ceiling unless the user explicitly chooses the existing allowance policy. The installed CLI and help prove only flag compatibility; live model entitlement, authenticated execution, actual event/usage behavior and POSIX dispatch remain T16 evidence gates.
